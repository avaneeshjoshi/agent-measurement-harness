# Caliper — current state

## Current milestone

On one machine, the measurement loop runs end to end: `caliper setup` extracts sessions from local Claude Code, Cursor, and Codex logs into schema-valid, content-free records; `caliper signals` computes git outcome signals (survival, rework, reverts, attribution) for the repos those sessions reference; `caliper classify` labels the traffic without reading content; `caliper replay` has produced a real three-tier quality/cost curve on 30 mined bug-fix tasks; and `caliper policy` presents the first draft routing policy (rp-0001) against the user's own traffic and records an accept/decline decision. Since 2026-08-23, collection also runs continuously: a launchd agent extracts hourly (activity-gated, watermarked), the CLI warns when collection lapses against each source's actual rotation window, and drift canaries watch for source-format decay. Everything downstream of the policy decision — actually changing agent configs, the trace layer, the judged eval track, the dashboard — is stubbed and labeled as such on screen. All of it has run on exactly one machine: the developer's own.

## Working today

Every entry here is implemented and has produced real numbers. A capability without an evidence line does not belong in this section.

**Log extractor (`caliper extract`, `caliper setup`)** — three source connectors (Claude Code JSONL, Cursor state/tracking DBs, Codex rollout JSONL) plus per-prompt units for the two sources that have them. Read-only over sources (SQLite snapshot-copied, enforced by test), content-free by default, idempotent by content hash.
*Evidence:* ADR-0004 (Codex structural validation, first run 2026-08-09: 21/43/21 sessions, 0 validation failures), ADR-0005 (cross-tool normalization). Current local tree (2026-08-23): 233 claude_code + 52 cursor + 24 codex session records (session schema 0.4.0), 991 prompt units (prompt_unit 0.1.1) — counts drift upward continuously now that collection is scheduled. Extractor tests in the suite cover read-only sources, idempotency, and the content boundary (all passing; the suite runs on every push and PR via `.github/workflows/ci.yml`). First-run backfill benchmarked 2026-08-24 against a synthetic six-month heavy-use history (3,000 sessions / 381,992 records / 390 MB, mixed sizes including a 12,000-record session and a fork family, seeded generator): **12.1 s** cold, 13.6 s idempotent re-run, on this machine — well inside what a first run may cost, so no progress machinery was added beyond the existing per-source working indicator. Everything Caliper produces about a user lives under `~/.caliper/` — extracted, derived, reports, state, logs, with the salt protected at the top of the tree — and **no code path can write user data into the repo**: `cli/paths.py` is the single path authority and the layout is enforced by test (ADR-0011, ADR-0012). Legacy trees migrate automatically, salt-preserving (`tests/test_paths.py`).

**Git-history production signals (`caliper signals`)** — blame-based survival at 30/60/90d horizons, 14-day rework, marker-only revert detection, evidence-only AI attribution, for exactly the repos the extracted sessions reference. Since ADR-0015, generated paths (versioned pattern list gen-0.1.0 + each repo's `.gitattributes linguist-generated`, overridable both directions) are excluded from line counting: work counts render, the excluded delta travels on every record, and a generated-only commit reads `excluded_generated` — the sixth absence word (DESIGN.md, sanctioned by ADR-0015). production_signal 0.3.0. Live re-run under the filter (2026-08-24, ADR-0015 table): Axlerate's line-weighted 30d survival corrected from 5.7% to 99.7% — the 3,013,346-line lockfile commit held nine lines of actual work — 16 mixed commits shrank, one commit flipped to `excluded_generated`, and the signals pass dropped from ~6 minutes to 36 seconds.
*Evidence:* ADR-0006 — first run 2026-08-09: 7 repos, 88 commits, 0 validation failures (production_signal 0.2.0, on disk); re-run 2026-08-24 under the blame-failure fix: 234 commits, three-way diff showed 0 records affected by the fabricated-zero pathway (ADR-0006 postscript). Ground-truth verified 2026-08-24 (ADR-0006 postscript 2): six known-answer events assert exact values in `tests/test_git_signals.py` (rework counts, abbreviated-sha revert linkage, never-0% for young commits, deletion-as-measurement, the generated-file skew as an executable fact), and a ten-commit hand audit against raw git agreed exactly on 9/10 — the one divergence was the hand script's own precedence error, resolved in the tool's favor. Revert linkage remains fixture-verified only: zero reverts exist in any real repo analyzed. Session→repo join rates: claude_code 95% (20/21), codex 81% (17/21), cursor 60% (26/43).
*Note on join rates:* the first-look report's coverage table shows different, higher figures (claude_code 100%, codex 91%, cursor 80%). Both are on disk; they are different instruments over different session sets. ADR-0006's numbers come from the actual session→git-toplevel join (`session_join_stats`) on the 2026-08-09 snapshot and are the citable join-rate measurement. The report column is a weaker proxy (does the session's project have a display-name mapping — self-described as approximate) computed over the current session set, which is now dominated by Caliper's own eval-harness sessions that all live in one repo. Cite ADR-0006, not the report, for join rates.

**Task mining + replay eval (`caliper replay mine|run`)** — mines historically-validated bug-fix tasks (hidden tests fail pre-fix, pass at fix) and replays them headless across model tiers under a locked config.
*Evidence:* ADR-0007 — 30 commons-lang tasks × 3 tiers, 90 eval_result records (0.3.0, on disk): fable-5 20/30 solved ($38.19), sonnet-5 19/30 ($15.85 list; $10.57 at billed intro rate per the ADR-0007 postscript), haiku-4.5 11/30 ($4.46). Total spend $61.08 including pilot. Caveat that travels with every use: commons-lang is in training data — tier-to-tier gaps are meaningful, absolute rates are not.

**Variance run (n_runs=3)** — the follow-up ADR-0007 gated any routing policy on.
*Evidence:* ADR-0008 — 10 tasks × 3 tiers × 3 reps, 90 records on disk ($73.49 list-equivalent). The fable/sonnet gap does not survive (p=0.645); the sonnet/haiku cliff does (p=0.026). 26/30 cells deterministic; ~7% of n=1 cells flipped outright.

**Classifier v0 (`caliper classify`)** — content-free rules classifier + observable-boundary segmenter, validated against the hand-labeled calibration set; `--validate` reruns the agreement measurement as one reproducible command (report written home-side per classifier version).
*Evidence:* ADR-0009 — prompt-grain agreement 53.1% (κ 0.41) against 81 human labels; segment-grain 38.5% (κ 0.24); segmenter reproduces 13/13 validatable calibration segments byte-exactly (validation report frozen at `data/evidence/adr-0009/validation_report.json`). Current output: 1,625 task_class records (0.1.0, 2026-08-24) across three unit grains — drifts upward with scheduled collection. (ADR-0009 cites 1,446 — that input snapshot is pinned at commit `a2dddd7` for recomputation; the live file has since been regenerated over newer extractions, is the current figure, and lives at `~/.caliper/derived/classes/` per ADR-0012.)

**First-look report (`caliper report`)** — self-contained HTML: spend by tool/model/project/day at list-price equivalents, task mix by cohort, git outcomes, coverage-and-honesty table.
*Evidence:* generated from current records at `~/.caliper/reports/first_look.html` (309 sessions); absent data renders "not recorded", never zero (enforced by test in `tests/test_report.py`). Fork/resume children — the one cross-file duplication vector (ADR-0002 finding 4) — are netted from spend and the netting is disclosed on the page and in the policy verdict ("N sessions (1 fork child netted from spend)"), never a silently smaller count (`tests/test_report.py`; live: 1 of 309 netted, ~0.5% of token volume).

**Local interactive view (`caliper serve`)** — a read-only HTTP server on 127.0.0.1 (ephemeral port, browser tab): the report's content live and sortable — since ADR-0017 with four server-side SVG charts (spend-over-time with tool/model split and quiet-days-as-gaps; task-mix proportion bars per cohort with unclassified in the absent gray; the cost×survival scatter with a labeled band for unplottable repos; token buckets per model), a 1d/7d/30d/90d/all range selector in URL state, and the savings framing headline ("at pay-as-you-go API rates — if a subscription covered it, that is what you saved"); every chart carries its n in a one-line panel header, hover is an instant pointer tooltip with the exact underlying figures (native SVG titles were measured unusable — ADR-0017 postscript 2), and clicks navigate only where a genuinely different destination exists (scatter point → repo), and the chart-category tokens were added to DESIGN.md by ADR-0017 rather than invented inline — plus the two views the static report cannot hold — repo detail (commits × survival/rework/attribution/generated-exclusion beside the sessions that referenced the repo) and session detail (tokens by bucket, cost, the classification rule that fired with its rationale, files as salted refs, and nearby commits labeled *temporal proximity, not attribution* — the trace layer is still stubbed and the page says so). One data layer with the report: serve renders `summarize(load_data(...))` and `caliper report` renders the same composition, pinned by an identity test, so the two surfaces cannot drift. Filters (date range, tool) are URL state applied before aggregation; freshness is re-read-per-request through an mtime-keyed bundle cache with the loaded-at stamp in the page footer. No policy view (ADR-0014's gate stands), no writes (asserted by byte-identity over the data tree), no network, no external assets.
*Evidence:* ADR-0016; `tests/test_serve.py` (10 tests: read-only walks of every route on populated AND bare homes, CLI dispatch, report-figure identity, proximity labeling with the window stated as unvalidated, absence-words-never-zero, empty-home and partial-machine states, URL filters, cache invalidation). Walked live 2026-08-24 on this machine's real data (313 sessions, 139-commit repo detail, full session detail) and on an empty HOME (every view one sentence + one action, zero files written) — the walkthrough caught four defects the unit tests had not, all fixed same-day and recorded in the ADR-0016 postscript, including the command being entirely unlaunchable while its 8 unit tests passed. The ±24h nearby-commit window is an unvalidated display choice and is labeled as such on-page — recorded in ADR-0016 precisely because the retention constant showed what an unmeasured display number does when left quiet. The report was restyled to the same DESIGN.md tokens in this work (the pre-DESIGN blue palette survives nowhere); before/after screenshots delivered with the walkthrough.

**Policy conversation (`caliper policy`, end of `caliper setup`)** — scans classified traffic against rp-0001, shows the overspend verdict, the quality/cost-per-tier charts with CIs, tier access status, and asks the apply question. **Development preview since ADR-0014**: every policy surface (command, post-extract nudge, setup step) gates on eval evidence from the user's own traffic — a fresh install gets one sentence, never a recommendation built from the author's shipped commons-lang evidence; it returns as a product surface when the router can derive a policy from the user's data.
*Evidence:* rp-0001 on disk (routing_policy 0.1.0, status **draft**, router_version `manual-adr-0008` — see Stubbed). Tier access gating per ADR-0010: tiers appear in recommendations only when proven by extracted traffic; unmeasured tiers render their access status instead of disappearing. See Known gaps for what the overspend number currently measures.

**Versioned pricing (`caliper pricing update`)** — dated price sheets with a LiteLLM cross-check; billed-rate-at-run-date convention.
*Evidence:* ADR-0007 postscript (caught the sonnet-5 intro-rate mispricing; records not rewritten, restated in citation); snapshots in `harness/replay/pricing_snapshots/`.

**Packaged install (`pipx install git+…@v0.2.0`)** — Caliper installs and runs without a source checkout: the wheel carries the record schemas inside the package (`caliper.assets`, resolved by the single path authority), pricing snapshots ship as package data, `--version` reports the distribution version, and the shipped surface is `setup` / `extract` / `signals` / `classify` / `report` / `serve` / `schedule` — every number from the user's own machine. `policy`, `replay`, `pricing update`, and `classify --validate` are development instruments: present in a checkout, refusing with a plain sentence in an installed copy (policy additionally gates on eval evidence from the user's own traffic — no borrowed commons-lang recommendation is ever handed to a fresh install).
*Evidence:* ADR-0014; verified 2026-08-24 by building the wheel, installing into a bare venv under a fake HOME with no checkout importable, extracting fixture logs (3 sessions, schemas from the packaged copy), and exercising all three dev gates. The CI smoke job repeats that install on clean ubuntu and macos runners on every push. A one-pass stranger walkthrough (empty machine / rotated logs / real logs → report → gated policy → uninstall) completed with zero blockers; six non-blocking observations are recorded in ADR-0014 addendum 2. Top-level packages renamed to `caliper.*` before the first wheel existed; post-rename the scheduled job was kickstarted and landed a real extraction with byte-identical unchanged records.

**Continuous collection (`caliper schedule`, `caliper extract --scheduled`)** — launchd agent, hourly while awake (launchd never fires in sleep; missed ticks coalesce on wake), activity-gated so idle ticks are one-line heartbeats that still count as coverage, mtime-watermarked so active runs are O(new), flock'd against concurrent runs, with a daily full pass that heals cross-file fork links. Gap warnings fire on any interactive invocation, per source and per machine: Claude Code's window is read from the user's own `cleanupPeriodDays` (default 30 as fallback), warnings escalate at-risk → loss with the derivation stated in the warning itself, and non-rotating sources (Codex, Cursor) get coverage-gap wording — a lapse there loses nothing (ADR-0011 postscript). Drift canaries alarm on unknown-shape/skip-rate jumps and field-coverage sinks, persisted to state so scheduled findings surface interactively. Full Disk Access is an explicit install-time choice (full: + daily signals; extraction-only: no permission needed), and install verifies the job from its own context via kickstart before claiming success. First-run honesty per DESIGN.md: absent sources render their status in words ("source not present" / "installed, but no session logs remain — rotates after ~30 days"), an empty machine gets one sentence and one action instead of zeros or a crash, permission failures name themselves with a recovery action, and every non-interactive prompt prints the conservative default it took and how to change it (`tests/test_first_run.py` — the first setup-flow tests). Content sidecars are a setup-time opt-in, off by default, local-only — **opted in and accumulating on this machine since 2026-08-24** (the teacher-labeling corpus, ADR-0009 follow-up: prompt text plus the `agent-name` session titles the drift counters surfaced, captured sidecar-only; `tests/test_extractor.py::test_agent_name_lands_in_sidecar_only`).
*Evidence:* ADR-0011 + its retention postscript; `tests/test_health.py` (22), `tests/test_collection.py` (10), `tests/test_schedule.py` (11), `tests/test_paths.py` (8) — suite total 89, all passing. Live on this machine since 2026-08-23: installed extraction-only, kickstart-verified, watermarked run examined 3 of 220+ artifacts. All three warning kinds (loss / at-risk / coverage) verified live with the derivation rendered in the sentence. Historical note: the warning's very first firing ran under the since-corrected 3-day constant and overstated loss — see the retention finding under Known gaps.

## Known gaps

- **Whatever rotated out before continuous collection was enabled is already lost.** Collection is continuous once installed (see Working today), and the measured retention picture is per-source: Claude Code rotates at `cleanupPeriodDays` (~30 days default; deletion boundary measured on this machine), Codex and Cursor don't rotate at all — so the permanently-gone set is Claude Code sessions that aged out before their first extraction, and backfill remains lossy by construction. Scheduling is also macOS-only (launchd); Linux needs the systemd user timer sketched in ADR-0011. And full-collection mode rests on a broad Full Disk Access grant — accepted explicitly at install, but a narrower mechanism (per-repo hooks, interactive-only signals) is recorded future work.
- **The retention constant itself was an instrument failure — caught, corrected, recorded (ADR-0011 postscript).** ADR-0009's n=1 observation (one log gone within 3 days) was generalized into `RETENTION_OBSERVED_DAYS = 3`; measurement on 2026-08-23 showed the real boundary is Claude Code's ~30-day `cleanupPeriodDays` (deleted at 45d, surviving at 29d; Codex files 193d old; Cursor cumulative) — the vanished log had simply crossed the 30-day line. A 10x-wrong threshold shipped inside the tool whose whole purpose is replacing assumed numbers with measured ones. It was caught the same day by doing exactly that, and the fix derives the window per source and per machine with the derivation printed in the warning. Kept here as a finding, not just a fix: n=1 over-generalization is the failure mode Caliper exists to catch, and it happened in Caliper's own instrument first.
- **Platform support is macOS-first and Windows is concretely unsupported.** Linux runs the whole shipped surface except background collection (launchd only; `caliper schedule` refuses in words — a systemd user timer is sketched in ADR-0011). Windows fails at import on the extract paths (`fcntl` is module-level in the collection runtime) and has never been tried; the README says so plainly so a Windows user learns it there, not from a traceback.
- **Never run off this machine.** Every number in this file is one solo developer's traffic on one laptop. It validates the instruments, not anyone else's usage.
- **The overspend verdict is currently measuring Caliper's own eval runs.** As of this review, all 46 frontier sessions the policy flow flags as overspend ($49.07 at list) are replay-harness traffic; organic overspend on this machine is ~$0. The screen discloses it ("46 of 46 are Caliper's own eval runs"), but the headline number is meaningless until organic frontier bug-fix traffic exists.
- **Costs are list-price counterfactuals, not real spend.** No agent log contains dollars (ADR-0001), and this machine's traffic is on subscription. Every dollar figure is "what this would have cost at API list rates," clearly labeled — but it has never been validated against a real invoice.
- **Cursor logs carry no tokens and no turns** (ADR-0004) — Cursor sessions are shape-only, unpriceable, and classified at session grain only.
- **The classifier's 53% agreement is the downstream bottleneck — and the cheap improvement paths are now measured dead ends.** Task-mix numbers, the policy flow's in-scope selection, and any future mix-weighted routing all inherit it. Strong on exploratory_qa and browser-verification, structurally blind to intent distinctions (bug-fix vs small feature, config vs code) — ADR-0009. The neighborhood-features experiment (rules-0.2.0, ADR-0013) was pre-registered, validated once against the 81 labels, and **withdrawn on a negative result** (50.6%/κ0.365 vs 53.1%/κ0.412; 1 of 7 predicted flips landed, 3 regressions; evidence frozen at `data/evidence/adr-0013/`): most human flow-context labels rest on content, not tool adjacency at any radius. The path forward is the content corpus (accumulating since 2026-08-24) and teacher labeling — not more metadata rules.
- **Format drift is now alarmed, not silent — but the thresholds are v0 judgment calls.** `additionalProperties: false` catches *new* fields; drift canaries (`cli/health.py`, thresholds recorded in ADR-0011) now cover the rest: unrecognized-shape and skip-rate jumps vs a pooled same-version baseline, and field-coverage sinks over trailing session windows — the removed-field case (ADR-0005's Codex git block) that used to degrade silently. Alarms persist to collection state and surface on the next interactive invocation (`tests/test_health.py`, 16 tests incl. version-bump non-trigger and small-n guards; counters found five undocumented claude_code record types on their first live survey). First live firing (2026-08-24): eight field-coverage alarms that trace to a cohort shift (eval-harness-heavy baseline vs organic recent traffic), not vendor drift — a predictable false-positive class now recorded in ADR-0014; cohort-aware windows are the designated fix, thresholds unchanged until then.
- **`session` and `task_class` schemas are still flagged REVIEW REQUIRED** (since ADR-0001). Everything downstream is built on provisionally-shaped records and a `0.1.0-provisional` taxonomy.

## Build order

Synthesized from the ADR follow-up lists; sequence is the current intent, not a commitment.

1. **Field-by-field review of `session` and `task_class`** — open since ADR-0001; everything downstream inherits their provisional shapes.
2. **Classifier: teacher labeling over the content corpus** — the neighborhood-features path was tried pre-registered and measured dead (ADR-0013); the corpus accumulating since 2026-08-24 plus LLM-judged labeling of a larger local sample is the remaining route to wider label sets before any learned classifier.
3. **Uncontaminated task source** — JIRA-enriched problem statements, re-run of the 7 all-fail tasks (ADR-0007 finding 4), then a non-public-repo mining source so absolute rates mean something.
4. **Apply engine v0** — native config writes with one-command revert, consuming the decision log the flow already writes.
5. **Trace layer v0** — session→commit joins with commit-time slack after session end (ADR-0006 finding 5), on the `project_ref` join key already validated in both directions.
6. **Web demo of the setup flow** (`docs/setup-demo-web-spec.md`), then the dashboard proper from the report's data model.

The judge track intentionally trails: its calibration set needs human raters (see Blocked).

## Blocked — needs a real team, not this machine

- **Taxonomy and unit-choice validation**: enterprise labels from multiple engineers are the promotion gate (ADR-0002, ADR-0009); solo self-labeled data cannot go further.
- **Segmenter's non-gap rules**: `branch_change` and `file_set_jump` have fired zero times on solo single-branch data (ADR-0002) — they need real branching and multi-module repos to be tested at all.
- **Review friction and revert linkage**: structurally invisible in solo direct-push repos — zero PRs, zero reverts across all 7 local repos (ADR-0006).
- **Judge calibration**: the 100–200 task human-rated set requires practicing engineers (~1hr each).
- **rp-0001 promotion draft→proposed**: requires uncontaminated or enterprise task sources, a classifier-derived mix weight, and production-signal triangulation (ADR-0008).
- **Cost validation**: list-price estimates need at least one org with API billing to compare against invoices.
- **Managed-org mode**: the setup flow's org-policy branch needs an actual managed org (Cursor Teams / Claude Code enterprise) to exist against.
